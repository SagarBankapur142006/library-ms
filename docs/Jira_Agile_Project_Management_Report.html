1. Executive Summary & Objectives

This comprehensive project documentation details the engineering and management processes implemented to design, build, and deploy a responsive Library Management System (LMS) web application. Managing software lifecycles in academic environments requires structured Agile methodologies. To achieve this, we implemented the Scrum framework inside Jira to organize requirement files, create backlog structures, estimate work complexity, and monitor daily tasks.

All software components of the Library Management System are fully functioning. The application features a React, TypeScript, and Vite frontend architecture, simulating transactional persistence via web LocalStorage. Key capabilities include Role-Based Access Control (RBAC), multi-criteria catalog search, inventory catalog management, circulation rules, fines calculations, and book reservations queues.

Key System Objectives Covered in Development:
  • Jira Project Setup: Configuring a Scrum Board and defining an 8-Epic WBS.
  • System Analysis: Drafting formal SRS specifications and creating Use Case and Activity Diagrams.
  • Database Architecture: Normalizing transactional data to 3NF and defining a relational ERD.
  • Role-Based Authentication: Implementing secure routing limits for Admins, Librarians, and Students.
  • Book & Member Inventory: Building forms for item CRUD configurations and registration logs.
  • Circulation Engine: Writing state management routines for checkouts, returns, and daily fine accruals ($1.00/day).
  • Borrowing Policies: Creating configurators to adapt limits (max loan count, checkout days, fine rates).
  • Reservation Queue: Setting up automated waitlists for out-of-stock items, allocating copies upon return.

4. Technical System Design & Database Schema

The Library Management System is built on a modern single-page application architecture. The frontend uses React and TypeScript, bootstrapped with Vite. Global application states are managed using React Context Providers (AuthContext and LibraryContext).

For the storage layer, the application implements a simulation library in storage.ts. This module reads/writes JSON datasets directly from window.localStorage, simulating transactional SQL operations like unique checks, table joins, and updates. This ensures stable persistence across page reloads.

Database Normalization (3NF) & Schemas

Database Table Primary Keys & Constraints Attributes List
users id (PK, Auto-Inc) email (Unique), password_hash, full_name, role (Admin/Librarian/Student), created_at
books id (PK, Auto-Inc) title, author, isbn (Unique), genre, total_copies, available_copies
transactions id (PK, Auto-Inc) book_id (FK), member_id (FK), issued_by_user_id (FK), issue_date, due_date, return_date (Nullable), status
fines id (PK, Auto-Inc) transaction_id (FK), fine_amount, payment_status (Paid/Unpaid), paid_date
reservations id (PK, Auto-Inc) book_id (FK), member_id (FK), reserved_at, status (Pending/Fulfilled/Cancelled)

5. Implementation Details of Key Features

  • 5.1 Authentication and Role-Based Guards Authentication uses standard forms mapping inputs against storage.ts records. Upon validation, the system saves the session details. Routes check permissions before rendering dashboard modules, ensuring RBAC limit enforcement.
  • 5.2 Book Inventory Management The book page enables Librarians to execute full CRUD operations. Input validations run automatically to prevent duplicates of ISBN values, check number bounds on copy allocations, and block deletions of books that are actively checked out.
  • 5.3 Circulation Rules & Overdue Calculations The checkout transaction verifies that a member exists, is active, and does not exceed the limit of five books. On checkout, the system decrements available copies. When a book is returned, the system increments availability and checks if the return date is past the due date. Overdue durations trigger an automated fine entry of $1.00 per day.
  • 5.4 Policy Configuration Panel The Settings page permits Administrators to alter default library settings. Variables like maximum borrow limits, checkout duration days, and daily fine rates can be edited directly.
  • 5.5 Reservation Queues When available copies of a book drop to zero, students can join a waitlist. The book page displays a "Reserve Book" button. Upon return of the book by another borrower, the circulation engine looks up pending reservations and auto-assigns the copy to the next student in line.

7. Agile Ceremonies & Project Management Reporting

To ensure high engineering excellence, we followed active agile rituals on our board:

  • Daily Standups: Standup comments are logged directly on active tickets (e.g. "Completed AuthContext login trigger, starting routing guards today. No blockers").
  • Sprint Retrospective Meetings: Retrospective tasks (e.g., Sprint 2 Retrospective meeting) summarize what went well, what could be improved, and action items.
  • Reporting Metrics: The board tracks Sprint Burndown charts, Velocity charts, and Cumulative Flow Diagrams (CFD) to measure performance.
